> [!info] 知识摘要
> **总结**
> - `5 / 2` 等于 `2`，因为两个操作数都是 `int`，Java 执行的是整数除法。
> - Java 整数除法向 `0` 截断，所以 `-5 / 2` 是 `-2`，不是 `-3`。
> - `%` 是求余，不是总为正的数学取模；要循环意义上的非负余数，用 `Math.floorMod()`。
> - `Integer.MIN_VALUE / -1` 不会抛异常，但会溢出并返回 `Integer.MIN_VALUE`，这类静默边界更容易被忽略。
>

## 一、`/` 先问类型，再做除法

`/` 不是只问“数学结果是多少”，而是先由操作数类型决定执行哪套除法规则。

```java
System.out.println(5 / 2);          // 2
System.out.println(5.0 / 2);        // 2.5
System.out.println((double) 5 / 2); // 2.5
System.out.println((double) (5 / 2)); // 2.0
```

`5` 和 `2` 默认都是 `int`，所以 `5 / 2` 是整数除法，结果只能是整数。想得到 `2.5`，必须在除法发生前让至少一个操作数变成 `double` 或 `float`。

最后一行容易坑：`(double) (5 / 2)` 是先算 `5 / 2` 得到 `2`，再把 `2` 转成 `2.0`。丢掉的 `.5` 不会复活。

| 表达式 | 结果 | 关键点 |
|---|---:|---|
| `5 / 2` | `2` | `int / int` |
| `5.0 / 2` | `2.5` | 浮点除法 |
| `(double) 5 / 2` | `2.5` | 先转操作数 |
| `(double) (5 / 2)` | `2.0` | 先整数除法，后转结果 |

`byte`、`short`、`char` 参与算术运算时会先提升成 `int`；`long / long` 也仍然是整数除法，只是结果类型更大，不会保留小数。

## 二、整数除法向 `0` 截断

整数除法不是四舍五入，也不是简单向下取整，而是向 `0` 截断。

```java
System.out.println(5 / 2);    // 2
System.out.println(-5 / 2);   // -2
System.out.println(5 / -2);   // -2
System.out.println(-5 / -2);  // 2
```

关键是 `-5 / 2`。数学结果是 `-2.5`，如果向下取整应是 `-3`，但 Java 返回 `-2`。

```text
 2.5  ->  2
-2.5  -> -2
```

同样，浮点数强转成 `int` 也不是四舍五入：

```java
System.out.println((int) 86.7);  // 86
System.out.println((int) -86.7); // -86
```

如果业务要表达明确的取整规则，就用 `Math.floor()`、`Math.ceil()`、`Math.round()`，不要靠强转暗示。

## 三、判断整除，看 `%`

如果问题是“`100` 能不能被 `9` 整除”，不要看 `100 / 9` 有没有小数。整数除法根本不会给你小数。

```java
System.out.println(100 % 10 == 0); // true
System.out.println(100 % 9 == 0);  // false
```

可以写成：

```java
public static boolean isDivisible(int a, int b) {
    if (b == 0) {
        throw new IllegalArgumentException("除数不能为 0");
    }
    return a % b == 0;
}
```

整数 `/` 和 `%` 遇到除数为 `0` 会抛 `ArithmeticException`：

```java
System.out.println(5 / 0); // ArithmeticException: / by zero
System.out.println(5 % 0); // ArithmeticException: / by zero
```

浮点除法不一样，它按 IEEE 754 规则得到特殊值：

```java
System.out.println(5.0 / 0); // Infinity
System.out.println(0.0 / 0); // NaN
```

## 四、`%` 的本质：余数由商定义

中文里常把 `%` 叫“取模”，但 Java 里的 `%` 更准确地说是**求余**。它不是先天保证非负，而是要和整数除法凑成这条恒等式：

```text
(a / b) * b + (a % b) == a
```

这是 Java 语言规范对整数余数运算的定义思路，见 [JLS §15.17.3](https://docs.oracle.com/javase/specs/jls/se17/html/jls-15.html#jls-15.17.3)。

正数时没什么戏剧性：

```java
System.out.println(5 / 2); // 2
System.out.println(5 % 2); // 1
// 5 == 2 * 2 + 1
```

负数时，整数除法向 `0` 截断，于是余数也被带出来：

```java
System.out.println(-5 / 2); // -2
System.out.println(-5 % 2); // -1
// -5 == (-2) * 2 + (-1)
```

所以“`%` 的结果符号跟左操作数一致”不是口诀本身，而是这个恒等式和整数除法规则共同推出来的结果。

| 表达式 | Java `%` |
|---|---:|
| `5 % 2` | `1` |
| `-5 % 2` | `-1` |
| `5 % -2` | `1` |
| `-5 % -2` | `-1` |

## 五、想要循环余数，用 `Math.floorMod()`

如果你要的是数组下标、星期偏移、环形队列这类“非负循环余数”，不要直接相信 `%`。

```java
int index = 0;
int size = 7;

System.out.println((index - 1) % size);          // -1
System.out.println(Math.floorMod(index - 1, size)); // 6
```

工程上建议把循环长度、数组长度这类除数明确约束为正数：`Math.floorMod(index, size)` 里的 `size` 应该满足 `size > 0`。如果 `size <= 0`，先处理参数错误，不要把它交给取模逻辑。

`Math.floorMod(a, m)` 和 `%` 的核心差异是：它基于 `floorDiv()`，结果符号跟除数一致。当 `m > 0` 时，结果一定落在：

```text
0 <= result < m
```

对比更直观：

| 表达式 | 结果 |
|---|---:|
| `-5 % 2` | `-1` |
| `Math.floorMod(-5, 2)` | `1` |
| `5 % -2` | `1` |
| `Math.floorMod(5, -2)` | `-1` |
| `-1 % 7` | `-1` |
| `Math.floorMod(-1, 7)` | `6` |

如果不想用 `floorMod()`，常见手动修正是：

```java
int r = a % m;
if (r < 0) {
    r += m;
}
```

这段代码只适用于 `m > 0` 且 `r` 来自 Java 的 `a % m`。因为 Java 余数满足 `-m < r < m`，所以负余数只要加一次 `m`，就会落回 `[0, m)`。这个技巧依赖 Java `%` 的语义，移植到其他语言或自定义除法规则时不要想当然。

## 六、容易漏掉的边界：`MIN_VALUE / -1`

除数为 `0` 会直接抛异常，这个大家通常知道。更容易漏掉的是这个：

```java
System.out.println(Integer.MIN_VALUE);      // -2147483648
System.out.println(Integer.MIN_VALUE / -1); // -2147483648
System.out.println(Integer.MIN_VALUE % -1); // 0
```

数学上，`-2147483648 / -1` 应该是 `2147483648`，但这个值超过了 `int` 的最大值 `2147483647`。

Java 的处理不是抛异常，而是发生整数溢出，结果仍然等于 `Integer.MIN_VALUE`。JLS 对 `/` 的这个特殊情况也有明确说明，见 [JLS §15.17.2](https://docs.oracle.com/javase/specs/jls/se17/html/jls-15.html#jls-15.17.2)。

`long` 也一样：

```java
System.out.println(Long.MIN_VALUE / -1L); // -9223372036854775808
System.out.println(Long.MIN_VALUE % -1L); // 0
```

这个边界常出现在绝对值、反向排序、符号翻转、边界比较里。尤其是 `Math.abs(Integer.MIN_VALUE)` 也还是负数，别把“取绝对值后一定非负”当铁律。

## 常见误区

> [!warning] `int / int` 如果除不尽，Java 会自动转成 `double`
> 不会。`int / int` 的结果就是整数。要浮点结果，必须让至少一个操作数先变成浮点类型。

> [!warning] `(double) (5 / 2)` 可以得到 `2.5`
> 不行。括号里的 `5 / 2` 已经先算成 `2`，外层强转只能得到 `2.0`。

> [!warning] `%` 的结果一定非负
> 不一定。Java 的 `%` 是求余，负数被除数会得到负余数；循环下标用 `Math.floorMod()`。

> [!warning] `Integer.MIN_VALUE / -1` 会抛异常
> 不会。它会溢出并返回 `Integer.MIN_VALUE`，真正会抛异常的是整数除以 `0`。

## 总结

| 问题 | 结论 |
|---|---|
| `5 / 2` 为什么等于 `2` | 两个操作数都是 `int`，执行整数除法 |
| 怎么得到 `2.5` | 让一个操作数在除法前变成 `double` 或 `float` |
| 整数除法怎么处理小数部分 | 向 `0` 截断 |
| 怎么判断整除 | `a % b == 0` |
| `-5 % 2` 为什么是 `-1` | `%` 要满足 `(a / b) * b + (a % b) == a` |
| 想要非负循环余数怎么办 | `m > 0` 时用 `Math.floorMod(a, m)` |
| `Integer.MIN_VALUE / -1` 会怎样 | 不抛异常，溢出后仍是 `Integer.MIN_VALUE` |

压狠一点：

```text
你以为 / 只是数学除法，其实操作数类型先决定规则。
你以为 % 是数学取模，其实它只负责把等式补完整。
你想要循环余数，答案是 size > 0 时的 Math.floorMod()。
```
